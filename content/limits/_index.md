Здесь собраны пределы firc: сколько чего можно завести, что бывает, когда предел достигнут, и чего firc не умеет. Большинство из них в обычной домашней сети не встретится.

## Роутер и система

- **Только Keenetic** с Entware, сборки для `aarch64`, `mipsel` и `mips`. OpenWrt и обычный Entware не поддерживаются.
- **Ядро** 3.4 и новее. firc рассчитан на роутеры от 256 МБ памяти; большие списки и пул занимают больше.
- **Ядро без IPv6.** Если в ядре роутера нет IPv6, демон не запустится, пока в настройках не выключено семейство IPv6 (раздел **Netfilter**).
- **Перезагрузка роутера.** Настройки, группы, туннели и закэшированные подписки переживают и перезапуск демона, и перезагрузку. Выданные адреса из пула переживают только перезапуск демона: после перезагрузки пул начинается заново.
- **Только в памяти.** Правила списков по ссылке, журнал, статистика запросов, итог захвата и каталог списков живут в памяти и пропадают при перезапуске демона. Списки после запуска скачиваются заново, и пока список не скачан, его правила не действуют.

## Что firc не видит

firc узнаёт сайт по DNS-запросу к роутеру. Мимо firc идёт трафик устройств, которые:

- пользуются своим DNS-over-HTTPS в браузере или системе;
- имеют DNS-сервер, прописанный вручную;
- ходят на заранее известный IP без DNS-запроса.

Найти такие случаи помогает [захват](../guide/journal/#захват). Для сервисов, которые ходят на известные адреса без DNS, есть правила-[подсети](../guide/groups/#подсети-протокол-и-порты).

Устройства, привязанные к политике Keenetic с собственным DNS-профилем или интернет-фильтром: firc перехватывает их DNS раньше прошивки, и имена вне групп firc не проходят через DNS-профиль политики.

## Группы и правила

| Что | Предел | Что будет сверх него |
|---|---|---|
| Работающих групп | 255 | группа 256 и дальше не поднимается, в журнале «mark field: limit reached», демон повторяет попытку |
| Интерфейсов у группы | от 1 до 4 | — |
| Интерфейсов на проверке, во всех группах вместе | 16 | 17-й не проверяется, в журнале предупреждение |
| DNS-серверов группы | от 1 до 4 | — |
| Портов у правила-подсети | 15, диапазон считается за два | — |
| Комментарий правила | 256 байт | — |
| Домен в правиле | 253 символа, часть между точками — 63 | — |
| Адресов одного устройства в выборе [устройств](../guide/devices/) | 64 | 65-й и следующие адреса устройства идут мимо группы |

- **Регулярные выражения.** Слишком тяжёлое регулярное выражение (очень много шагов перебора) firc прерывает, и правило просто не срабатывает, без ошибки. Пишите регулярки с `^…$` и без вложенных повторов.
- **Задержка перехода.** Новое правило действует для устройства, которое уже спрашивало это имя, только когда истечёт его DNS-кэш: до **Потолка TTL** (300 секунд) для сайтов групп и до **TTL ответов вне правил** (60 секунд) для остальных.
- **Домен из группы с адресом в домашней сети** (например, сервер в LAN, который отвечает на домен из списка) работать не будет: firc уводит его в интерфейс группы.

## Списки по ссылке

| Что | Предел | Что будет сверх него |
|---|---|---|
| Списков у группы | 1 | нужно два — сделайте две группы |
| Размер скачанного списка | 8 МБ | «the list is too big», список не загружается |
| Rule-set `.srs` после распаковки | 16 МБ | список не загружается |
| Перенаправлений при скачивании | 5 | «too many redirects» |
| Время на скачивание | 15 секунд | ошибка загрузки у списка |
| Предпросмотров одновременно | 2 | просьба подождать |

- **Число правил в списке** не ограничено, но большой список стоит памяти и времени: список в 313 тысяч правил занимает около 21 МБ, а поиск по нему — около полсекунды на каждое нажатие клавиши.
- **Из rule-set** берутся только правила по адресу назначения. Правила с условиями по источнику, процессу и подобному пропускаются целиком (см. [Списки](../guide/lists/#какие-форматы-понимает-firc)).
- **Список, ни разу не скачанный** с запуска, firc повторяет сам: через 1 секунду, потом всё реже, до раза в минуту.

## Пул адресов

| Что | Предел | Что будет сверх него |
|---|---|---|
| Доменов в пуле (**Доменов в пуле, максимум**) | 65 536 по умолчанию | сайт получает blackhole-адрес и не открывается, но и не уходит мимо группы |
| Кусок пула на группу | 254 адреса IPv4 (`/24`) | группа берёт следующий кусок |
| Кусков в пуле `198.18.0.0/15` | 511 | как при переполнении: blackhole-адрес |

- Домен, который есть в двух группах для разных устройств, занимает в пуле два места.
- У сайта группы для устройства один настоящий адрес на семейство: если у домена несколько адресов IPv4, устройство пойдёт на один из них.
- Адреса пула нельзя использовать на роутере ни для чего другого, пока работает firc.
- Каждый выданный адрес — одно правило в ядре. На слабом `mipsel` при 65 тысячах доменов это добавляет около 25 мс к первому пакету нового соединения.
- Первый ответ на новое имя может ждать до 0,8 секунды, пока firc записывает правило в ядро.

## DNS

| Что | Предел |
|---|---|
| Одновременных запросов к вышестоящему DNS | 100 по умолчанию; сверх — новые запросы отбрасываются |
| Ожидание вышестоящего DNS | 5 секунд по умолчанию |
| Ожидание DNS группы через туннель | 1 секунда, потом отвечает обычный DNS роутера |
| Цепочка CNAME | 12 имён |

- **DNS группы на адресе в домашней сети** (например, Pi-hole) работать не будет: DNS группы спрашивается через её туннель. Все ответы придут через обычный DNS роутера, и группа покажет это меткой **DNS группы сбоит**.
- **IPv6 в туннелях VLESS** не поддерживается, поэтому на запросы AAAA для групп на туннеле firc отвечает пустым ответом, и устройства идут по IPv4.

## Интерфейсы

| Что | Предел |
|---|---|
| **Интервал проверки** | от 10 до 3600 секунд, по умолчанию 30 |
| **Таймаут проверки** | от 1 до 30 секунд, по умолчанию 5 |

Рабочим считается только ответ 204. Проверка идёт по IPv4. Туннели VLESS не проверяются запросом, их состояние берётся у самого туннеля.

## Туннели и узлы

| Что | Предел | Что будет сверх него |
|---|---|---|
| Туннелей | 8 | — |
| Источников у туннеля | 256 | — |
| Узлов, которыми пользуется туннель | 256 | узлы сверх этого остаются в списке с пометкой **сверх 256 узлов** и не используются |
| Строк в списке узлов | 2048 | лишние строки не показываются, хотя счётчики их учитывают |
| Активных узлов | от 1 до 8 | — |
| Своих заголовков подписки | 16, значение до 512 байт | — |
| Фильтр по имени | 1024 байта | — |
| Размер подписки | 8 МБ | ошибка в строке подписки |
| Обновление подписки | вручную или от 10 минут до 7 дней | — |
| Описание туннеля | 63 байта (31 кириллическая буква) | — |
| Соединений через туннель | около 320 на поток, до 4 потоков | новое соединение отклоняется, в журнале сообщение |

**Как поднять нужные узлы в 256.** Исключённые узлы места не занимают, а узлы, расставленные вручную, идут первыми. Поэтому: отфильтруйте подписку **Фильтром по имени**, исключите ненужные переключателем или перетащите нужные наверх.

Чего tunvless не умеет:

- **протоколы** — только VLESS; VMess, Trojan, Shadowsocks, Hysteria и другие пропускаются;
- **IPv6** — ни сервер с адресом IPv6, ни IPv6-трафик через туннель;
- **транспорты** — TCP, WebSocket, HTTPUpgrade, gRPC и xhttp; нет `h2` (HTTP/2 как отдельного транспорта) и QUIC; для xhttp нет режима `stream-down` и обфускации; нет TCP с `headerType=http`;
- **шифрование** — `none`, TLS и REALITY; поток только `xtls-rprx-vision` и только поверх TCP;
- **отпечаток** — только Chrome и Firefox; другие значения `fp` в ссылке (`safari`, `random` и т. п.) дают Chrome;
- **ECH** — только встроенный в ссылку, без запроса в DNS.

Узел, который tunvless не может использовать, остаётся в списке с причиной.

**Проверить узлы** проверяет узлы по очереди, по несколько секунд на узел, так что проверка сотен узлов идёт долго. Одновременно идёт только одна проверка.

**TCP через ядро** работает только для IPv4 TCP; UDP и IPv6 идут через TUN.

## Входящие порты

| Что | Предел |
|---|---|
| Портов у туннеля | 16 |
| Соединений через входящие порты | 128 на туннель |
| UDP-сессий SOCKS5 | 32 на туннель, по 16 адресов назначения в каждой |
| Логин и пароль | до 255 байт, в логине нет двоеточия |

- Порт слушает только на адресе IPv4 роутера в сегменте LAN из настроек.
- Нет SOCKS5 BIND и обычного HTTP-прокси без CONNECT.
- Адреса назначения IPv6 отклоняются, UDP к имени домена (а не к адресу) отбрасывается.

## Журнал, статистика и захват

| Что | Предел |
|---|---|
| Событий DNS и захвата в журнале | последние 4096 |
| Сообщений демона | по 512 INFO и DEBUG, 256 WARN и ERROR |
| Длина сообщения | 240 байт, имя группы в событии — 47 байт; длиннее обрезается |
| Статистика запросов | 24 часа, 16 384 пары «имя — устройство»; при переполнении забываются самые редкие |
| Строк статистики | первые 550 по числу запросов, остальные находит поиск |
| Устройств в фильтре статистики | 12 адресов |
| Сколько firc помнит вопросы для захвата | 30 минут, 8192 адреса |
| Захват | 5 минут, один одновременно, до 500 пакетов в секунду на интерфейс |

- В журнал попадают только устройства, для которых работает хотя бы одна группа.
- Захват не читает имя сайта из QUIC (HTTP/3) — такие соединения он узнаёт только по адресу — и не видит имя, если начало TLS-соединения разбито на несколько пакетов.

## Веб-интерфейс

- **Порт** 666, если занят — 999, 1666, 2666 или 9999. Если заняты все, демон работает без веб-интерфейса.
- **Вход** всегда по паролю пользователя роутера; выключить нельзя. После трёх неудачных попыток подряд — пауза в секунду.
- **Одно сохранение** — до 1 МБ. Очень большой набор своих правил (не из списка) может не сохраниться: браузер покажет обрыв соединения. Большие наборы правил держите в списках по ссылке.
